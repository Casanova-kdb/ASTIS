# ASTIS v1.1.0 Release Notes

## Release Summary

ASTIS v1.1.0 is the first engineering-hardened post-MVP release. It builds on the v1.0 task-management and recommendation MVP by adding account settings, task scoring criteria, AI-assisted handbook import, and a protected CI-based delivery workflow.

## Included Features

### Account and Study Settings

- Users can update their display name and change their password after authentication.
- Users can maintain a study profile used by the recommendation workflow.
- Each task can carry its own scoring criteria so task-specific context is separated from user-level preferences.

### AI Handbook Import

- Authenticated users can upload PDF and DOCX module handbooks.
- The backend extracts readable text temporarily and does not permanently store uploaded files.
- DeepSeek can identify possible task drafts when configured.
- A local parser provides a safe fallback if DeepSeek is disabled, unavailable, or returns unusable content.
- Users review and edit every extracted draft before it becomes a real task.
- Missing information remains empty for the user to complete; source dates are preserved exactly.

### Engineering Quality

- GitHub Actions runs the Spring Boot test suite on Java 17.
- GitHub Actions installs the locked frontend dependencies and produces a Vue production build on Node.js 22.
- `develop` and `main` are protected: changes must be merged through a PR after `Backend tests` and `Frontend build` pass.
- The project includes a PR template for recording scope, user-story evidence, verification, UI evidence, and documentation changes.
- Integration-test cleanup now respects task-to-user foreign-key dependencies, making the full suite stable on clean CI runners.

## Known Limitations

- The project is not containerised or deployed to a cloud environment yet.
- Automated frontend interaction or end-to-end tests are not included yet.
- Recommendation scoring is rule-based rather than trained on a large historical dataset.
- Very long handbooks may need section-aware parsing in a future iteration.
- Redis caching is intentionally deferred until recommendation query behaviour has been measured and refined.

## Upgrade Notes

For local development, keep API keys and database credentials in ignored local configuration files. Do not commit `DEEPSEEK_API_KEY`, JWT secrets, or database passwords.

## Next Planned Work

The next iteration will focus on recommendation explanation and query performance before adding Redis caching, Docker support, and deployment documentation.
