# ASTIS v1.2.0 Release Notes

## Release Summary

ASTIS v1.2.0 turns the existing recommendation workflow into a more
explainable and practical study-planning experience. It combines the work from
Sprints 10, 11, and 12: recommendation explanations, Redis-backed caching, and
a deterministic Study Plan Generator.

## Included Features

### Explainable Recommendations

- Every ranked task includes readable factors explaining its position.
- Delay risk has a separate explanation from the general priority summary.
- The recommendation page presents these factors without changing the existing
  scoring formula.
- User task statistics are loaded once per recommendation request and reused
  across all active tasks.

### Redis Recommendation Caching

- Ranked recommendation lists are cached per internal user ID.
- The default cache lifetime is configurable and set to 10 minutes.
- Creating, updating, completing, reopening, or deleting a task invalidates
  only the affected user's recommendation cache after the transaction commits.
- Redis is treated as an optimisation: recommendation requests continue with
  database calculation when Redis is unavailable.

### Study Plan Generator

- Authenticated users can generate plans for a configurable 1-to-14-day window.
- Active tasks are processed in recommendation order using deadlines, estimated
  effort, delay risk, daily capacity, and preferred study time.
- Large tasks are split into sessions of no more than two hours.
- The API reports overdue work, missing estimates, insufficient capacity, and
  work outside the selected planning window instead of silently dropping it.
- The Vue Study Plan page presents summary metrics, daily sessions, warnings,
  empty states, and unscheduled work on desktop and mobile layouts.

## API Addition

```http
GET /api/study-plans?days=7
Authorization: Bearer <jwt>
```

The endpoint is included in Swagger/OpenAPI and accepts planning windows from
1 to 14 days.

## Engineering Decisions

- Study plans are generated by deterministic Java rules rather than delegated
  to an AI model. This keeps scheduling explainable and testable.
- Generated plans are calculated on request and are not persisted in this
  release.
- Redis stores derived recommendation output and never replaces MySQL as the
  source of truth.
- Cache failures are logged without making the recommendation API unavailable.

## Known Limitations

- Generated study plans cannot yet be dragged, edited, or saved as calendar
  events.
- Per-weekday availability and calendar-provider integration are not included.
- Automated frontend end-to-end tests are not included yet.
- Docker packaging and cloud deployment remain planned work.
- Redis must be installed separately when caching is enabled for local use.
